# aoostar-lcd

Глазастая статус-панель на передней крышке домашнего сервера AOOSTAR WTR MAX
(960×376 USB-serial LCD, ~4.3"). Сделана для чтения с расстояния в те
моменты, когда владелец на неё смотрит:

- диск отказал или критичный сервис лежит без maintenance-флага → весь экран
  мигает красным с надписью **АВАРИЯ** и списком сломанного;
- сервер загружается → страница **ЗАПУСК** показывает, какие сервисы ещё
  поднимаются, вместо ложной тревоги «всё лежит»;
- сервер останавливается → **ВЫКЛЮЧЕНИЕ / ПЕРЕЗАГРУЗКА** показывает, что уже
  остановлено и что ещё гаснет;
- что-то ещё не так → статус-бар желтеет и называет проблему;
- HDD шумят → чтение/запись по дискам, прогресс scrub/SMART-теста, самые
  нагруженные датасеты;
- CI идёт долго → какие пайплайны идут, сколько уже и сколько ждут;
- иначе: температуры, нагрузка, свободная память и место.

Язык интерфейса: русский или английский — ключ `[display] language` в конфиге.

## Что на экране

**Авария.** Любое из этих событий заменяет все страницы полноэкранной
тревогой, мигающей красным/чёрным каждый кадр (~1.3 с — время полной
перерисовки панели): настроенный диск пропал или SMART выдал `FAILED`, лист
пула не `ONLINE` (показывается меткой диска), пул не `ONLINE`, либо критичный
сервис лежит без maintenance-флага. Одна проблема — крупно; несколько
группируются по объекту в 1–3 колонки одним размером шрифта; после 12 строк
последняя читается «и ещё N». Упавшие timer-задачи, CI-контейнеры шагов и
warning-простои тревогу не поднимают.

Остальные страницы делят 64-пиксельный **статус-бар**: состояние слева
(`ВСЁ РАБОТАЕТ` зелёный / `ПРОБЛЕМА: …` янтарный / `ОБСЛУЖИВАНИЕ: …`
серый), чипы (`алерты N`, `CI 2 · 17 мин`, `HDD 71%`), точки страниц и часы.

| Страница | Когда | Содержимое |
|---|---|---|
| Запуск | свежая загрузка, сервисы ещё поднимаются | крупно `поднято / всего`, секундомер с начала загрузки, строка на каждый неготовый сервис |
| Сводка | всегда, двойной показ | температура/нагрузка CPU, свободная ОЗУ, температура/утилизация GPU, занятость HDD (+чтение/запись) |
| Проблемы | пока что-то горит | сначала простои, затем алерты Grafana и упавшие задачи, с возрастом и счётчиком |
| CI | пока идут сборки или очередь | репозиторий, номер пайплайна, шаг, ветка, секундомер; длина очереди и ожидание |
| HDD | busy ≥ 10 %, scrub/resilver или SMART-тест | строка на каждый HDD: busy %, чтение МБ/с, запись МБ/с, температура или тест |
| ZFS | вместе с HDD | каждый настроенный пул: здоровье, свободно, скан; самые нагруженные датасеты |
| Температуры | всегда | CPU, GPU, ОЗУ, вентилятор, все NVMe и HDD (4 × до 3 плиток) |
| Нагрузка | всегда | топ по CPU и памяти (контейнеры, CI, сервисы) |
| Место | всегда | строка на том и пул: свободно, всего, метр, занято % |

Крупные значения — 84–108 px, детали — 38–42 px, мельче 34 px ничего нет.
Цвет кодирует только состояние (пороги — в конфигурации).

## Загрузка и выключение

Юнит systemd упорядочен только за локальными ФС и собственным serial-устройством
панели (не за Docker), поэтому слежение за загрузкой начинается так рано,
как позволяет железо. Пока не все наблюдаемые стеки/юниты активны — или не
истёк `services.startup_window_secs` (600 с) с момента загрузки — страница
ЗАПУСК заменяет ротацию, и критичные простои сервисов не поднимают тревогу;
аппаратные аварии (пропавшие диски, деградировавшие пулы) работают всегда.

Когда systemd останавливает юнит при выключении или перезагрузке,
`ExecStopPost` запускает `aoostar-lcd shutdown`: он читает
`systemctl list-jobs`, чтобы отличить ВЫКЛЮЧЕНИЕ от ПЕРЕЗАГРУЗКИ, и показывает
остановку наблюдаемых сервисов — `остановлено 5 / 13`, кто ещё жив, счётчик
контейнеров — кадр в секунду до 80 с (внутри 90-секундного стоп-бюджета).
После юнита ничего не упорядочено, поэтому параллельное слежение никогда не
задерживает выключение: цикл завершается, как только всё наблюдаемое
остановлено. Если выключения нет (ручной stop, рестарт при деплое) — панель
просто гаснет. При выключении панель гаснет в конце; после перезагрузки
последний кадр остаётся на экране, пока его не сменит страница ЗАПУСК.

## Источники данных (только чтение)

| Источник | Интервал | Для чего |
|---|---|---|
| `/proc`, `/sys` (stat, meminfo, diskstats, hwmon, cgroup v2) | 1 с | CPU, память, температуры, вентиляторы, скорости дисков, ворклоады |
| `/proc/spl/kstat/zfs/<pool>/objset-*` | 1 с | логический I/O датасетов («кто нагружает HDD») |
| Docker Engine API (`/run/docker.sock`) | 5 с | нездоровые/перезапускающиеся контейнеры, шаги Woodpecker CI (только `CI_*` env) |
| `systemctl` | 5 с | неактивные настроенные стеки/юниты, failed-юниты, флаги обслуживания |
| `systemctl list-jobs` | при остановке | различение выключения и перезагрузки |
| `nvidia-smi` | 5 с | GPU |
| Grafana alert API (Viewer-токен) | 15 с | горящие алерты; `alert_family` решает простой это или алерт |
| Prometheus | 30 с | длина очереди Woodpecker и старейшее ожидание |
| `zpool status -j` / `zpool list` | 30 с | здоровье, ошибки, не-`ONLINE` листы (с метками дисков), прогресс scrub/resilver |
| `smartctl -j -H -c -A` | 60 с | температура HDD, вердикт SMART, прогресс самотеста |

Источник, который не отвечает, недолго держит последнее значение и затем
показывает `--`; недоступный Grafana сам становится проблемой.

## Установка

Требуется Linux с systemd, Rust (1.88+), `libudev-dev` и `pkg-config`.

```bash
git clone https://github.com/nietonchique/aoostar-lcd
cd aoostar-lcd
cargo build --locked --release -p aoostar-lcd
sudo install -Dm0755 target/release/aoostar-lcd /usr/local/bin/aoostar-lcd
sudo install -Dm0644 config.example.toml /etc/aoostar-lcd.toml  # затем отредактировать
sudo install -Dm0644 dist/aoostar-lcd.service /etc/systemd/system/aoostar-lcd.service
sudo systemctl daemon-reload && sudo systemctl enable --now aoostar-lcd
```

Проверить конфигурацию без записи в панель:

```bash
aoostar-lcd check --config /etc/aoostar-lcd.toml
```

## Конфигурация

`config.example.toml` документирует каждый ключ. Секции: `[display]`
(устройство, язык, секунды страницы, heartbeat, смещение часов),
`[thresholds]` (границы warning/critical по метрикам), `[[disk]]` /
`[[volume]]` (что наблюдать; диски — только by-id), `[zfs]` (пулы),
`[services]` (systemd-шаблоны и юниты, которые должны быть активны, окно
загрузки, каталог maintenance, Docker-сокет), `[alerts]` (опциональный
Grafana), `[ci]` (опциональный Prometheus).

## Разработка

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace

# Офлайн-превью всех страниц из фикстуры снапшота
cargo run -p aoostar-lcd -- preview --config config.example.toml \
  --fixture crates/aoostar-lcd/fixtures/boot.json --out-dir /tmp/lcd

# Превью живого состояния хоста
sudo aoostar-lcd snapshot > /tmp/live.json
cargo run -p aoostar-lcd -- preview --config /etc/aoostar-lcd.toml \
  --fixture /tmp/live.json --out-dir /tmp/lcd
```

CLI: `run` (водить панель), `check` (проверить конфиг + один сбор),
`snapshot` (снапшот в JSON), `preview` (отрисовать страницы в PNG),
`shutdown` (прогресс выключения/перезагрузки; вызывается из `ExecStopPost`),
`off`.
