# Конфигурация

Один TOML-файл (`/etc/aoostar-lcd.toml`); каждый ключ документирован в
поставляемом [`config.example.toml`](../config.example.toml).
English version: [configuration.md](configuration.md).

| Секция | Ключи | Смысл |
|---|---|---|
| `[display]` | `device` | USB-serial устройство панели (путь by-id) |
| | `language` | код языка из `i18n/<код>.toml` — в бинарник вшиты `en` и `ru` |
| | `i18n_dir` | каталог с дополнительными/переопределёнными таблицами переводов |
| | `page_seconds` | секунд на страницу ротации (Home — вдвое дольше) |
| | `heartbeat` | файл, обновляемый после каждого кадра (по умолчанию `/run/aoostar-lcd/heartbeat`) |
| | `clock_utc_offset_minutes` | сдвиг часов статус-бара от UTC |
| `[thresholds]` | `cpu_temp_c`, `gpu_temp_c`, `nvme_temp_c`, `hdd_temp_c`, `ram_temp_c`, `memory_used_percent`, `space_used_percent`, `hdd_busy_percent`, `ci_minutes` — каждые `[warning, critical]` | значения на границе и выше берут её цвет; warning `hdd_busy_percent` также добавляет страницу HDD в ротацию |
| `[[disk]]` | `label` (1–4 знака), `kind` (`nvme`/`hdd`), `by_id` | наблюдаемые диски в порядке конфигурации. Только by-id пути — пропажа диска или SMART `FAILED` поднимает АВАРИЮ |
| `[[volume]]` | `label` (1–5 знаков), `path` | файловые системы на странице «Место» |
| `[zfs]` | `pools` | наблюдаемые пулы; первый — основной (имена датасетов без префикса). Лист не `ONLINE` или пул не `ONLINE` поднимает АВАРИЮ |
| `[services]` | `templates` | systemd-шаблоны, загруженные экземпляры которых должны быть активны (например `homelab-compose@` для Docker Compose стеков) |
| | `units` | отдельные юниты, которые должны быть активны |
| | `startup_window_secs` | окно загрузки: сколько секунд страницей ЗАПУСК владеет экран (по умолчанию 600) |
| | `maintenance_dir` | `<dir>/<имя>` или `<dir>/ALL` помечает намеренно остановленный юнит |
| | `docker_socket` | путь к сокету Docker Engine (по умолчанию `/run/docker.sock`) |
| `[alerts]` *(опционально)* | `grafana_url`, `grafana_host`, `token_file`, `local_node`, `outage_families` | API алертов Grafana: горящие алерты попадают на страницу проблем; семейства из `outage_families` эскалируются до АВАРИИ |
| `[ci]` *(опционально)* | `prometheus_url` | Prometheus для метрик очереди Woodpecker |

## Семантика, которую стоит знать

- **Обслуживание vs простой.** Наблюдаемый юнит в неактивном состоянии при
  существующем `<maintenance_dir>/<subject>` (или `<dir>/ALL`) показывается
  серым (обслуживание), а не простоем. Каталог живёт на tmpfs — перезагрузка
  его очищает.
- **Проблемы сливаются по субъекту.** Несколько алертов одного сервиса
  становятся одной строкой со счётчиком; простои выше алертов, затем
  серьёзность, затем возраст.
- **Цвет — это состояние, не декорация.** Каждый порог — пара `[warning,
  critical]`; ничто другое на панели цвет не использует.
- Список `[[disk]]` авторитетен для аварий: пропавший диск или SMART `FAILED`
  поднимают АВАРИЮ даже в окне загрузки.
